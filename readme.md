Учебный веб-симулятор производственной системы по Теории ограничений. Проект предназначен для самостоятельного обучения студентов через песочницу и объясняющие сценарии.

Подготовлены концепт, план и первая очередь задач. Реализованы основа React/TypeScript/Vite/Vitest и первая автономная сборка с минимальным SVG и переключением RU/EN. Добавлены независимые от DOM модули точной арифметики, проверки линейной конфигурации, неизменяемого RunConfig и снимков состояния. Реализованы FIFO, перенос, резервирование и выпуск с сохранением стоимости и происхождения. Добавлен производственный календарь с обедом, переносом операций и точным горизонтом. Добавлена событийная основа с согласованным шагом и защитой от устаревших завершений. Источники push связаны с календарём, очередью и общим складом. Работает независимая от DOM детерминированная линия с обработкой, буферами, календарными паузами и физическим выходом. Runner управляет прогоном порциями, паузой, шагом, скоростью и повтором. На странице показана настоящая SVG-линия с очередями, прогрессом, причинами простоя и передачами. Доступны запуск, пауза, продолжение, шаг, скорость, остановка и новый прогон. Можно выбрать равномерный поток, рост очереди или блокировку тесным буфером. После запуска выбор примера зафиксирован до нового прогона.

Сборка создаёт самостоятельный `dist/index.html`. Его можно скопировать отдельно и открыть в браузере двойным щелчком без сети и сервера. Тот же файл можно разместить на статическом хостинге, в том числе в подкаталоге. Node.js и npm нужны только для сборки из исходников.

## Основные решения

Используемый стек: TypeScript, React и Vite. Автономная однофайловая сборка реализована через vite-plugin-singlefile 2.3.4. Будущий движок использует дискретно-событийную модель и не зависит от интерфейса. Несколько материалов, рецепты, сборка и разделение потоков входят в первую версию.

Входные и выходные буферы настраиваются у постов и наследуют глобальные значения, если не переопределены. Вариативность воспроизводится через seed. Конфигурация фиксируется при старте; изменения проверяются новым прогоном, в том числе через A/B. Длительность выбирается для конкретного урока или эксперимента.

Схема должна наглядно показывать движение материала, рост очередей, загрузку и причины простоя. Ускорение, пауза и шаг позволяют наблюдать поток и разбирать его причины без обязательного перехода к графикам.

Проект размещён в [yafarkin/tocsim](https://github.com/yafarkin/tocsim) вместе с полной историей коммитов. Основная ветка `master`; начальный коммит GitHub с MIT-лицензией сохранён объединением историй без перезаписи. Для чтения документов зависимости не нужны.

После завершения каждой задачи изменения проверяются и фиксируются Git-коммитом. Push и публикация требуют отдельного поручения.

Работа выполняется ровно по одной задаче. Перед следующей требуется ответ пользователя на вопрос о её запуске.

Перед задачей оценивается её объём; для большой реализации предлагается разбиение на подзадачи. Основной принцип: «НЕ ПЕРЕУСЛОЖНЯТЬ!». Подробные правила находятся в `agents.md`.

## Разработка

Используется Node.js 24.15.0, указанный в `.nvmrc`, и npm 12.1.0. Прямые зависимости зафиксированы точными версиями, полный состав зависимостей находится в `package-lock.json`.

Из корня проекта выполнить:

```sh
npm ci
npm run dev
```

Dev-сервер доступен только локально. Адрес выводится в терминале. Это способ работы разработчика; готовый `dist/index.html` открывается без сервера.

| Команда | Назначение |
|---|---|
| `npm run dev` | Запуск Vite для разработки |
| `npm run typecheck` | Строгая проверка TypeScript без генерации файлов |
| `npm test` | Однократный запуск тестов Vitest |
| `npm run test:watch` | Vitest с повторным запуском при изменениях |
| `npm run build` | Проверка типов и production-сборка в `dist/` |
| `npm run preview` | Локальный просмотр уже собранного `dist/` |
| `npm run check:dist` | Проверка однофайлового артефакта и SHA-256 |
| `npm run ci` | Тесты, типы, сборка и проверка артефакта |

Команда `npm test` выполняет 257 тестов движка, runner и схемы. Точная арифметика описана в [doc/ARITHMETIC.md](doc/ARITHMETIC.md), формат конфигурации в [doc/CONFIGURATION.md](doc/CONFIGURATION.md), материальный учёт в [doc/INVENTORY.md](doc/INVENTORY.md), календарь в [doc/CALENDAR.md](doc/CALENDAR.md), событийная основа в [doc/EVENTS.md](doc/EVENTS.md), источники в [doc/SOURCES.md](doc/SOURCES.md), работающая линия в [doc/SIMULATION.md](doc/SIMULATION.md), управление прогоном в [doc/RUNNER.md](doc/RUNNER.md), схема и браузерная приёмка в [doc/FLOW_SCHEME_CHECK.md](doc/FLOW_SCHEME_CHECK.md).

Для получения HTML выполнить `npm ci`, затем `npm run build` и открыть `dist/index.html`. При распространении достаточно одного файла. Хранение данных для текущей страницы не требуется.

В № 9 проверены TypeScript, production-сборка и работа HTML в Google Chrome через `file://` без сети и HTTP в подкаталоге. Подробности, версия браузера и ограничения находятся в [doc/AUTONOMOUS_BUILD_CHECK.md](doc/AUTONOMOUS_BUILD_CHECK.md).

В № 18 готовая схема проверена в подключённом Chrome по HTTP в подкаталоге; автономное открытие file:// без сети с запуском, паузой и RU/EN подтверждено пользователем вручную. Автоматический инструмент блокирует этот протокол; это ограничение не обходилось.

## CI и публикация

GitHub Actions проверяет pull request и master. Успешный master автоматически публикует проверенный dist/index.html на GitHub Pages. Сайт доступен на [GitHub Pages](https://yafarkin.github.io/tocsim/). Первая удалённая проверка и деплой прошли; протокол и команды в [doc/CI.md](doc/CI.md).

В № 19 полная панель и три примера проверены в Chrome по HTTP в подкаталоге. Пользователь подтвердил итоговый file:// без сети. Первая очередь этапов 1–4 завершена; предложение следующей очереди находится в [doc/COMPLETE_EXAMPLE_CHECK.md](doc/COMPLETE_EXAMPLE_CHECK.md).

В шапке доступен выбор системной, тёмной и светлой темы с иконкой. Выбор запоминается при доступном localStorage; без сохранения приложение продолжает работать. Тема не меняет прогон. Проверки и ограничения описаны в [doc/THEME_CHECK.md](doc/THEME_CHECK.md).
