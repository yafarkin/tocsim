# TOC

Учебный веб-симулятор производственной системы по Теории ограничений. Проект предназначен для самостоятельного обучения студентов через песочницу и объясняющие сценарии.

Подготовлены концепт, план и первая очередь задач. Реализована основа клиентского проекта: минимальная React-страница, строгий TypeScript, Vite и Vitest. Симуляционная логика пока отсутствует.

Планируемый результат сборки представляет собой самостоятельный HTML-файл, который открывается локально в браузере и может размещаться на GitHub Pages. Интерфейс будет доступен на русском и английском языках.

## Основные решения

Используемый стек: TypeScript, React и Vite. Автономная однофайловая сборка запланирована в задаче № 9 и пока не реализована. Будущий движок использует дискретно-событийную модель и не зависит от интерфейса. Несколько материалов, рецепты, сборка и разделение потоков входят в первую версию.

Входные и выходные буферы настраиваются у постов и наследуют глобальные значения, если не переопределены. Вариативность воспроизводится через seed. Конфигурация фиксируется при старте; изменения проверяются новым прогоном, в том числе через A/B. Длительность выбирается для конкретного урока или эксперимента.

Схема должна наглядно показывать движение материала, рост очередей, загрузку и причины простоя. Ускорение, пауза и шаг позволяют наблюдать поток и разбирать его причины без обязательного перехода к графикам.

Git-репозиторий инициализирован локально. Для чтения документов устанавливать зависимости не требуется.

После завершения каждой задачи изменения проверяются и фиксируются Git-коммитом. Push и публикация требуют отдельного поручения.

Работа выполняется ровно по одной задаче. Перед следующей требуется ответ пользователя на вопрос о её запуске.

Перед задачей оценивается её объём; для большой реализации предлагается разбиение на подзадачи. Основной принцип: «НЕ ПЕРЕУСЛОЖНЯТЬ!». Подробные правила находятся в `agents.md`.

## Разработка

Используется Node.js 24.15.0, указанный в `.nvmrc`, и npm 12.1.0. Прямые зависимости зафиксированы точными версиями, полный состав зависимостей находится в `package-lock.json`.

Из корня проекта выполнить:

```sh
npm ci
npm run dev
```

Dev-сервер доступен только локально. Адрес выводится в терминале. Это способ работы разработчика; готовый продукт по-прежнему должен открываться одним HTML без сервера.

| Команда | Назначение |
|---|---|
| `npm run dev` | Запуск Vite для разработки |
| `npm run typecheck` | Строгая проверка TypeScript без генерации файлов |
| `npm test` | Однократный запуск тестов Vitest |
| `npm run test:watch` | Vitest с повторным запуском при изменениях |
| `npm run build` | Проверка типов и production-сборка в `dist/` |
| `npm run preview` | Локальный просмотр уже собранного `dist/` |

Продуктовых тестов на этапе основы проекта пока нет. Для проверки запуска Vitest без искусственных тестов используется `npm test -- --passWithNoTests`. Обычная команда `npm test` намеренно завершится ошибкой при отсутствии тестовых файлов; постоянное разрешение пустого набора не включено.

В задаче № 8 проверены повторная установка из lock-файла, проверка типов, сборка, запуск Vitest без тестов и HTTP-ответы dev-сервера для страницы и преобразованных TSX-модулей. Браузерная приёмка автономного `file://` относится к № 9. Текущая сборка содержит HTML и отдельные JS/CSS-файлы и ещё не является автономной поставкой.
