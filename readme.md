# TOC

[Открыть симулятор](https://yafarkin.github.io/tocsim/) · [CI и публикации](https://github.com/yafarkin/tocsim/actions/workflows/ci-pages.yml)

Учебный браузерный симулятор Теории ограничений для самостоятельного обучения студентов. Сейчас работают производственные цепочки, разделение потока, сборка нескольких материалов, конечные буферы, общий сырьевой склад, смены/обед и базовая вариативность обработки. Это промежуточная реализация, а не законченный набор уроков и редактор.

SVG-схема показывает фактические очереди, резерв, работу, нехватку компонентов, блокировку и передачи. Доступны запуск, пауза, продолжение, шаг полной отметки, скорость, остановка и новый прогон. Есть пять технических примеров: равномерная линия, очередь, блокировка, разделение и сборка. Они используют общий движок, а не отдельную демонстрационную модель.

Рядом со скоростью находятся CV и seed. CV 0 даёт постоянное время, положительный CV задаёт логнормальные длительности с прежними средними. CV/seed и пример фиксируются после старта, скорость и язык остаются доступны. Движок 0.11.0, RNG counter32-fixed-lognormal-1, снимок 9. Проверки и границы в [doc/VARIABILITY.md](doc/VARIABILITY.md).

В шапке иконка циклически меняет системную/тёмную/светлую тему, кнопка RU/EN переключает язык. Выбор темы запоминается при доступном localStorage. Без сохранения приложение продолжает работать; прогоны и CV/seed в storage не записываются.

## Самостоятельный HTML

Сборка создаёт один `dist/index.html` со встроенными JS/CSS и без обязательных сетевых ресурсов. Его можно скопировать отдельно и открыть двойным щелчком без сервера. Тот же файл работает на статическом хостинге, в том числе в подкаталоге. Node.js и npm нужны только для сборки из исходников.

Последняя версия проверена в Chrome по HTTP в подкаталоге. Инструмент запрещает автоматическую навигацию file://; предыдущая ручная offline-приёмка № 18/19 не выдаётся за проверку новой версии. Firefox/Safari и численные межбраузерные эталоны RNG предстоит проверить при общей приёмке. Подробности в протоколах ниже.

## Разработка

Стек: TypeScript, React, Vite и Vitest. Версии закреплены в package.json/package-lock.json. Node.js 24.15.0 указан в .nvmrc, npm 12.1.0. Однофайловая сборка использует vite-plugin-singlefile 2.3.4. Движок не зависит от DOM, React, storage и системных часов.

Из корня проекта:

```sh
npm ci
npm run dev
```

Dev-сервер доступен локально, адрес выводится в терминале. Это способ разработки; для готового HTML сервер не нужен.

| Команда | Назначение |
|---|---|
| `npm run dev` | Vite для разработки |
| `npm run typecheck` | Строгий TypeScript без генерации |
| `npm test` | 295 тестов движка, runner и представления |
| `npm run test:watch` | Vitest с повторным запуском |
| `npm run build` | TypeScript и production `dist/index.html` |
| `npm run preview` | Локальный просмотр готового dist |
| `npm run check:dist` | Один HTML, встроенные ресурсы и SHA-256 |
| `npm run ci` | Тесты, build и check-dist |

Для получения файла выполнить npm ci, затем npm run build. При распространении достаточно одного HTML, сохранение не является условием работы.

## Git и публикация

Основной репозиторий [yafarkin/tocsim](https://github.com/yafarkin/tocsim), единственная рабочая ветка master с upstream origin/master. Полная история и начальная MIT-лицензия сохранены без перезаписи. Заголовки и описания коммитов пишутся на английском; отдельные ветки/worktree для задач не создаются.

После завершения задачи выполняются проверки, обновляется трекер, создаётся коммит и по постоянному поручению пользователя сразу выполняется push. Новый вопрос на каждый push не нужен. Успешный CI публикует проверенный HTML на GitHub Pages; PR не деплоится. Перед следующей задачей требуется явный ответ пользователя. Текущая команда bfe сохраняет контекст, а не разрешает начать № 30.

Обработочные партии поддержаны в конфигурации движка: последовательные повторения или одновременный цикл с полным резервом входов. Движок учитывает транспортный порог, последний остаток и частичную выгрузку. Настройки партий и их наглядное представление в интерфейсе остаются следующей согласованной частью. Проверки описаны в [doc/BATCHES.md](doc/BATCHES.md).
