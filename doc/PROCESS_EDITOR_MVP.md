Дата: 2026-11-03. Основание: пользователь попросил спланировать фундамент редактора, простую линейную цепочку, список процессов в localStorage и импорт/экспорт JSON. № 145 является документальной задачей. № 146 и № 152 (хранение) завершены. № 153 (JSON) и общая № 147 завершены на уровне функций. Интерфейс № 148 реализован, живая приёмка пока не проведена. Запуск № 149 реализован. Сквозная приёмка № 150 завершена, линейный MVP принят в проверенном объёме Chrome. Общая № 38 остаётся открытой.

## Объём и порядок

Объём средний для фундамента и большой для всего MVP. Затронуты модель конфигурации, хранение, формы, App и подключение существующих Runner, схемы и отчётов. Основная неопределённость связана с отделением пользовательской конфигурации от текущих форм примеров и проверкой допустимого подмножества модели.

По новому поручению линейный MVP выделяется из № 38 раньше остальных отложенных продуктовых блоков. Прежнее правило «полный редактор последним» сохраняется для оставшейся части. Завершение DBR, всех уроков, A/B и URL не является зависимостью линейного MVP. Реализация каждой части требует отдельной команды; текущий запрос разрешает планирование.

## Что получает пользователь

Пользователь открывает раздел «Мои процессы», создаёт процесс с исходной цепочкой из трёх постов и меняет его название. Он добавляет пост в конец, удаляет пост или перемещает его кнопками вверх/вниз. Минимум один пост, максимум 30 по существующему ограничению пользовательского интерфейса. Связи между соседями строятся автоматически. Первый пост получает сырьё из одного виртуального источника, выход последнего становится готовым продуктом.

У каждого поста доступны название, среднее время обработки и CV, входной и выходной буферы. Глобальные буферы и переопределения используют существующие правила наследования. Доступны seed и горизонт в сменах; календарь берётся из существующей базовой конфигурации и явно показывается. Исходный пример и подписи единиц фиксируются в № 146. Время вводится в минутах и переводится в миллисекунды существующей модели. Числа количества хранятся в принятом строковом формате.

На каждом посту один производственный рецепт с одним входом и одним выходом 1:1, последовательная обработка по одной единице и порог передачи 1. Начальные физические запасы нулевые. Переналадки, обслуживание, брак и подмена выключены, затраты нулевые, политика push. Материалы и рецепты создаются автоматически с понятными именами; отдельные справочники для них в MVP не нужны. Скрытые условия видны в описании процесса.

Пользователь сохраняет несколько именованных процессов, открывает их, сохраняет изменения, создаёт копию и удаляет выбранный процесс с подтверждением. Одинаковые названия допустимы, записи различаются по ID. Встроенные уроки и примеры остаются отдельно. Копирование произвольного технического примера в редактор не входит в MVP.

Команда «Запустить» использует существующие схему, управление и отчёты. Пауза, шаг, скорость, остановка и повтор работают по прежним правилам. При активном или приостановленном прогоне параметры заблокированы. Для изменения создаётся независимая копия, прежний результат остаётся связан со своим RunConfig. Несохранённый процесс можно запустить или экспортировать после успешной проверки.

## Фундамент и форматы

Единственная модель процесса есть существующий `EditorConfig` из `src/engine/config.ts`. Общий `compileConfig(unknown)` проверяет его и создаёт неизменяемый `RunConfig`. Не вводить вторую модель расчёта или новый движок. `ConfigError` уже содержит путь, объект и объяснения RU/EN.

Добавить чистые операции создания цепочки, добавления, удаления и перестановки постов. Проверка линейного подмножества дополняет общий валидатор требованиями интерфейса, но не повторяет его предметные правила. Проверять одну связную цепочку с одним источником, отсутствие обходных ветвей и точное соответствие поддерживаемым настройкам. Нельзя молча сбрасывать неподдерживаемые поля импортированного процесса.

ID поста сохраняется при переименовании и перемещении. Связи, материалы и рецепты обновляются согласованно при структурной правке; несвязанные объекты не пересоздаются без причины. Сохранение, открытие и импорт с экспортом сохраняют ID внутри конфигурации. Копия получает новый ID записи библиотеки и новый ID конфигурации; внутренние ID локальны конфигурации.

Поля формы с незавершённым числом живут в памяти отдельно от последней корректной конфигурации. Сохранение, экспорт и запуск выполняются после проверки. При уходе с несохранёнными правками предлагается сохранить или отбросить их; не обещается восстановление незавершённой формы после закрытия вкладки. Для MVP достаточно явного сохранения, отдельная система автосохранения и полная история undo/redo отложены.

В localStorage каждая запись лежит в собственном ключе `toc.process.<id>`. Запись содержит `schemaVersion`, `id`, `revision`, `updatedAt` и `config: EditorConfig`. Список получается чтением ключей своего префикса, отдельный индекс не нужен. Создание и изменение одной записи требуют одной записи значения. Ключ предпочтения `toc.uiMode` остаётся независимым.

JSON одного процесса содержит `format: "toc-process"`, `schemaVersion: 1` и `config: EditorConfig`. Версия оболочки и версия EditorConfig проверяются отдельно. Seed, календарь и настройки запуска уже входят в EditorConfig; их не дублировать. Локальные revision и updatedAt в переносимый файл не включать. Экспортируется выбранный процесс. Архив всей библиотеки не входит в первый MVP.

## Надёжность хранения и импорта

При доступном localStorage список восстанавливается после перезагрузки. Сохранение не требуется для расчёта. Доступ к storage и все чтения/записи обрабатывают исключения; при отказе остаётся список в памяти вкладки и статус RU/EN с предложением экспортировать JSON. Успешное сохранение в память нельзя показывать как сохранение на диск. Переполнение не удаляет старые процессы и чужие ключи.

Повреждённая запись не мешает открывать остальные. Её ключ сохраняется до явного удаления пользователем; неизвестную версию нельзя перезаписать как пустую библиотеку. Для формата версии 1 миграция из несуществующей версии 0 не нужна. При будущих изменениях формата обязательны проверяемые миграции с сохранением старых данных при ошибке.

Перед обновлением или удалением записи повторно прочитать revision. Если другой экземпляр приложения сохранил новую версию, предложить перечитать её или сохранить свою копию. После отказа записи держать локальные изменения в памяти. Полная синхронизация вкладок и гарантии атомарной совместной работы не входят в MVP.

Импорт через выбор файла: проверить размер до чтения (до 2 МБ), JSON, оболочку, версию, общий валидатор и линейное подмножество (до 30 постов). Показать имя, число постов, условия и ошибки RU/EN. Только после принятия создать новую запись с новым ID, даже при совпадении исходного ID. Ошибка и отмена не меняют библиотеку и текущую форму. Имена выводить как текст, содержимое файла не исполнять.

Валидная сборка, развилка или процесс с другими неподдерживаемыми настройками получает понятное сообщение «MVP поддерживает линейную цепочку» с конкретной причиной. Импорт не обрезает процесс до цепочки. Обмен старым необёрнутым EditorConfig и URL-код пока не обещаются.

Сохраняются только конфигурации. Снимки, временные ряды, результаты и текущая секунда прогона не попадают в localStorage/JSON. После открытия восстанавливаются условия для повторного запуска. Перенос между автономным HTML и сайтом выполняется JSON; сохранения привязаны к доступной области браузера.

## Хранение № 152 от 2026-11-04

Пользователь согласовал разделение № 147 и разрешил только хранение. № 152 выполнена в src/editor/process-storage.ts, 19 проверок в src/editor/process-storage.test.ts. Модуль пока не подключён к App. Переносимый JSON № 153 и интерфейс № 148 не реализованы.

openProcessStorage принимает необязательную функцию доступа к Storage. list возвращает копии записей с признаком persisted, issues возвращает ошибки чтения. save(id, config, expectedRevision) сохраняет проверенную конфигурацию. Для новой записи expectedRevision=0. После успешной записи revision увеличивается на один. При отказе запись остаётся в памяти с последней сохранённой revision, persisted=false и ошибкой RU/EN. remove(id, expectedRevision) проверяет сохранённую revision; при отказе доступа удаление действует только в памяти, вызывающий код получает persisted=false. После повторного открытия могут вернуться записи, удалённые только из памяти.

Конфликт, повреждение и неизвестная версия не затирают исходную запись. Ошибка конфигурации при явном сохранении выбрасывается существующим валидатором до изменения списка. Повреждённые записи сохраняются, их удаление через UI пока не подключено. Перечитать браузерный список можно новым openProcessStorage. Полной синхронизации вкладок нет.

## Интерфейс № 148 от 2026-11-04

Раздел «Мои процессы» подключён к App отдельно от уроков и Runner. ProcessEditor.tsx содержит библиотеку, формы, подтверждения перехода/удаления и импорт с предварительным просмотром. process-form.ts хранит поля строками, создаёт независимый EditorConfig только после проверки. Неявные общие буферы сохраняют существующие правила движка.

Память, постоянное сохранение, конфликт и несохранённая форма показаны раздельно. Перечитывание одного процесса не удаляет остальные записи в памяти. Копия получает новые ID записи и конфигурации.
