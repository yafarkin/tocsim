## Цель и разрешения

Пользователь хочет, чтобы веб и CLI работали с одной моделью и одним JSON. Веб нужен прежде всего для визуализации, а CLI для постановки воспроизводимых экспериментов. Различия в формах и командах допустимы при общей расчётной логике. Пользователь просит объяснять задачи простыми словами и выполнять их небольшими частями.

Последняя команда пользователя была `bfe`. Она разрешает обновить передачу и связанные документы, проверить их, сделать английский коммит и отправить его в `origin/master`. Следующая реализация не выбрана. Вопрос об отдельных буферах был объяснён, но пользователь не поручал добавить эти формы. Исследовательские № 169, 170 и 171 запланированы, каждая требует отдельной команды.

Работайте в `master`. Делайте коммит и push после проверки одной согласованной задачи. Проверяйте CI и Pages после крупных изменений или пачки. Для этого документального bfe отдельно ждать новой публикации не требуется. Публикацию `@toc/engine` в npm пользователь отклонил.

## Общий JSON, CLI и завершение прогона

- № 173 ввела оболочку `toc-process` версии 3. Внутри неё `config` использует схему модели 1, а необязательное `web` хранит координаты `layout.positions`, порядок `displayOrder` и цвета `materialColors`. CLI пропускает `web`. Оба потребителя читают оболочки версий 1 и 2 и старый объект `EditorConfig` в корне. Формат записи браузерной библиотеки имеет свою версию 2.
- № 174 перевела импорт, библиотеку, экспорт и запуск веба на компилятор движка. Веб показывает формы для поддерживаемых конфигураций и открывает остальные в редакторе JSON. Лимит браузерного импорта и экспорта составляет 2 МиБ. Некорректные данные блокируют сохранение, копирование, запуск и экспорт до исправления.
- № 175 добавила формы материалов, нескольких источников, поставок, начальных запасов склада и буферов и нескольких входов рецепта. Для каждого входа задаются материал и расход. На поле можно соединить поставщика любого материала из комплекта. После сохранения и перезагрузки сборка из одной столешницы и четырёх ножек дала 10 столов из запаса 40 ножек. Веб и CLI дали одинаковый выпуск.
- № 176 документировала поля, команды, совместимость старых файлов и готовый пример сборки. Этот пример проверен в обоих режимах CLI. Обычный запуск из файла и stdin дал `delivered: "10000000"` в миллионных долях единицы и завершился в `32400000` мс с причиной `horizon`. Удаление `web` дало тот же результат. [Формат, пример и команды](ENGINE_API.md#общий-json-файл-процесса).

Источники `virtual` подают сырьё без ограничения запаса в пределах заданного прогона. Источники `warehouse` расходуют начальный складской запас. Можно сочетать оба режима для разных материалов. Источники одного материала используют один режим и делят складской запас. Конечный склад прекращает поставки при исчерпании. Обычный прогон в обоих интерфейсах доходит до `durationMs`, конца последней смены, даже если сырьё закончится раньше. Выбор источника не меняет условие завершения.

Отдельная вместимость каждого материала уже работает в движке через `kind: "materials"`. Такой файл запускается в CLI и вебе. В «Моих процессах» для этой настройки пока нужен JSON. Если пользователь выберет формы, проверка готовности состоит в том, чтобы задать в вебе разные лимиты, сохранить и переоткрыть процесс, а затем получить те же лимиты и выпуск из экспорта через CLI. Полная № 38 остаётся открытой и включает также формы циклических планов и других параметров, пока доступных через JSON.

```sh
npm run build:engine
node packages/engine/dist/cli.js assembly.json > result.json
node packages/engine/dist/cli.js --bottleneck - < assembly.json > bottleneck.json
```

У CLI один флаг `--bottleneck`. Поиск использует один алгоритм с вебом и сравнивает принятый выпуск на заданном горизонте после ускорения каждого поста на 10 процентов. Буферы фиксируются, конечные продукты сравниваются отдельно. При случайности используются три парных seed. Возможны кандидат, равная группа, неоднозначность и отсутствие прироста. Это поиск по выпуску, а подсветка показывает пути через пост по графу. Правило подсветки уже принято в № 134–137. [Поиск и контрольные результаты](BOTTLENECK_SEARCH.md), [контракт CLI](ENGINE_API.md#cli-в-репозитории).
