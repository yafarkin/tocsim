## Черновик, связи и запуск

Session хранит последнюю корректную config, ProcessDraft, saved, layout и savedLayout. Черновик содержит текстовые поля, материалы с назначением, поля рецептов и routes. Неполные числа, разрыв схемы и некорректные маршруты живут в памяти текущей формы. configFromDraft собирает копию и проверяет её через compileEditableProcess. Сохранение, копирование, экспорт и запуск отключены до успешной проверки. Черновик не подменяет последнюю запись библиотеки или результат. При уходе предлагаются сохранение, отбрасывание и отмена; незавершённую схему надо исправить или отбросить. Восстановление черновика после закрытия вкладки не обещается.

ProcessRoutes.tsx создаёт, меняет и удаляет маршруты через формы. Начало, конец и материал редактируются явно. Чтобы подключить другой материал, сначала можно выбрать входной материал в рецепте и назначение материала. Сам жест эти поля не меняет. Дубли, циклы, отсутствующие маршруты, неизвестные узлы и несовместимые материалы полностью проверяет общий движок перед применением.

На поле выход есть у источника и каждого поста, вход у каждого поста и market, даже при разорванной схеме. Связь создаётся перетаскиванием выхода на вход или двумя нажатиями. С клавиатуры доступны Tab, Enter и Space. Есть предварительная линия, подпись выбранного выхода/материала и подсветка подходящих входов. Escape, кнопка отмены, отпускание в пустом месте, pointercancel и потеря захвата отменяют жест. Панель выбора сохраняет размер, поле не смещается при начале/отмене. На узком экране кнопка отмены расположена отдельной строкой.

process-connections.ts проверяет предлагаемое соединение независимо от незавершённых остальных маршрутов: существование концов, совпадение материала, назначение готового продукта для market, отсутствие дубля, самосвязи и нового цикла. Обход завершается и при уже циклическом черновике. connectProcessNodes возвращает новый список и не меняет другие поля. nextConnectionId общий для формы и поля, учитывает все ID конфигурации и текущие несохранённые маршруты. Новые ID участвуют в calculationHash, поэтому восстановление удалённых связей с другими ID может изменить хеш при прежнем расчётном результате.

Во время работы/паузы текущая запись заблокирована для правок, сохранения и удаления; порты отключены, незавершённый жест сбрасывается. Можно создать независимую копию. Новый запуск или уход к урокам требует остановки/завершения текущего прогона. ProcessPlayback использует собственный Runner и захваченный неизменяемый RunConfig; схема, отчёты и поиск получают эти условия. Старый результат остаётся в памяти до следующего запуска, не смешивается с уроками и не записывается в JSON/localStorage. Архива результатов нет.

## Поле и расположение

Карточки перетаскиваются за заголовок. Стрелки клавиатуры двигают на 10 пикселей, Shift со стрелками на 50. Escape, pointercancel и потеря захвата отменяют незавершённое перемещение. Есть сброс расположения и ссылки к формам постов. Поле прокручивается в двух направлениях. Перемещение меняет только геометрию, не маршруты и не расчёт.

ProcessLayout = {positions: {id,x,y}[]}. ID узлов уникальны, координаты целые 0–20000. Перекрытия разрешены. При добавлении узлы получают автоматические позиции, удалённые исключаются. layoutNodes включает все источники и посты даже в разорванном или циклическом черновике и не зацикливается. Схема запущенного прогона использует свою автоматическую раскладку, свободные координаты относятся к редактору. Layout отдельно участвует в сохранении, копировании, JSON и признаке правок.

## Хранение, JSON и API

Запись хранится в ключе `toc.process.<id>`: schemaVersion=2, id, revision, updatedAt, config:EditorConfig, layout:ProcessLayout. Отдельного индекса нет. ID записи отделён от config.id, внутренние ID при копировании сохраняются. revision у памятной новой записи равна 0; перед обновлением/удалением она перечитывается. Это обнаружение конфликта, не атомарная синхронизация вкладок.

openProcessStorage предоставляет list(), issues(), save(id,config,expectedRevision,layout), remove(id,expectedRevision), read(id). Выдаваемые данные независимы. Отказ хранения оставляет данные в памяти с persisted=false и пояснением RU/EN. Неудачная запись не повышает revision. read перечитывает одну запись, сохраняя остальные памятные процессы. При отказе удаления запись убирается только из памяти, браузерная запись может остаться; UI это объясняет. Повреждённые/будущие записи не затираются, остальные доступны.

JSON: format=toc-process, schemaVersion=2, config:EditorConfig, layout:ProcessLayout. EditorConfig остаётся версии 1. Записи/файлы прежней версии 1 читаются с пустым layout.positions и автоматической раскладкой. Миграция выполняется в памяти. Открытие не переписывает старую запись, явное сохранение пишет версию 2 и повышает revision. Старое приложение не обязано понимать новые файлы/записи версии 2.

exportProcessJson(config,layout) проверяет конфигурацию, расположение и размер. parseProcessDocument/readProcessDocumentFile возвращают {config,layout}. Прежние parseProcessJson/readProcessJsonFile проверяют весь документ и возвращают только EditorConfig для конфигурационных потребителей. Лимит UTF-8 2 МиБ (2097152 байта), размер файла проверяется до чтения и повторно по тексту. Неизвестные поля оболочки отклоняются. Ошибки ConfigError RU/EN содержат путь. Локальных revision/updatedAt, снимков и результатов в файле нет.

Предпросмотр не меняет библиотеку; только принятие импорта создаёт запись с новым ID записи и config.id. copyImportedProcess копирует только конфигурацию, UI отдельно переносит layout. Копирование технических примеров с неподдерживаемыми настройками не подключено. Сохранение и JSON используют compileEditableProcess и принимают валидные развилки поддерживаемого подмножества. Сборки с несколькими входами и остальные неподдерживаемые параметры отклоняются без обрезания данных. Расширение допустимого графа в № 163/164 не меняло оболочку версии 2.

## Решения пользователя, которые нельзя потерять

Проект является простым учебным сайтом для любопытствующих и студентов. ## Текущий поиск узкого места

Кнопка «Поиск узкого места» использует применённые условия RunConfig, а не черновики полей. Она доступна до запуска, на паузе и после остановки/завершения, недоступна во время воспроизведения. Поиск отдельно прогоняет весь заданный горизонт с начала, включая разогрев, и не меняет текущие время/скорость/статус/выход Runner или таблицы уроков.

Для каждого поста все времена обработки его строк уменьшаются на 10%, с округлением до миллисекунды и минимумом 1 мс. Сохраняются партии, планы, распределения/CV (с поправкой округления границ), качество, переналадки, обслуживание, источники, начальные запасы и календарь. Поддержаны constant/lognormal/uniform/triangular. В копиях фактические ёмкости из resolved фиксируются явными значениями по материалам до ускорения, чтобы наследуемые буферы на долю смены не пересчитались вместе со временем.

При случайности (CV>0 или 0<p<1 для дефекта) выполняются три парных seeds: текущий, +1, +2 по модулю 2^32. Без случайности достаточно текущего seed. Это маленькая серия, не статистическое доказательство. Годный принятый выпуск сравнивается точно по каждому конечному продукту; разные продукты не суммируются, процентного деления на исходный выпуск нет.

Пост входит в список лидеров, если в каждой паре не уменьшает ни один продукт и увеличивает хотя бы один относительно исходника. Его результат также должен не уступать ускорению любого другого поста по каждому продукту в каждой паре. Один лидер: outcome=candidate. Несколько лидеров имеют одинаковые векторы в каждой паре: outcome=tied. Разные лучшие посты между seeds или обмен продуктов: ambiguous. Если положительного прироста вообще нет: noGain. Пустой список не означает, что у процесса нет ограничений; метод проверяет одиночное ускорение, а не все сочетания совместных изменений.

Актуальный BottleneckResult: productIds, samples, stationIds:string[], outcome=candidate|tied|ambiguous|noGain. Одиночного stationId в результате больше нет. В samples: seed, baseline:string[] и outputs с отдельными stationId/quantities. Только память, новой сохраняемой схемы нет. Таблица показывает выпуск и парное изменение; при нескольких seeds диапазоны. Старые частичные/отменённые результаты не публикуются.

Поиск последовательный, порциями до 64 отметок и примерно 8 мс с возвратом управления через таймер; компиляция и одна отметка сами не прерываются. Вызов не обращается к DOM. Отдельного Worker/сервера/очереди заданий нет. Результат привязан к calculationHash. Смена расчётных условий отменяет поиск, сбрасывает таблицу и рамки. Язык/режим/тема сохраняют результат; новый Runner с теми же условиями не делает его устаревшим. Начало воспроизведения отменяет выполняемый поиск через React effect; проверка должна дождаться обновления интерфейса.

## Подсветка и её смысл

Каждый найденный пост получает оранжевую пунктирную рамку 5 px, dash 10/4, и подпись «Кандидат в ограничение». Цвет светлой темы #c75b0a, тёмной #fb923c. Цвета реальных состояний постов сохранены. FlowDiagram принимает bottleneckStationIds; сам поиск не назначает drum DBR.

flowThroughStation в diagram.ts выделяет структурные маршруты от источников через пост к готовому продукту четырьмя обходами достижимости. Для нескольких кандидатов используется объединение routeIds без повторов. Все проходящие ветви включаются, обходные и соседняя ветвь перед сборкой не выдаются за проходящие через найденный пост. Ветвление не сводится произвольно к одному маршруту. Стрелки потока более толстые, пунктирные, цвета accent; есть пояснение RU/EN и пометки текстового списка. Координаты, анимация передач и расчёты модели прежние.

Это связи конфигурации, а не доказанный фактический критический путь изделия. История операций для такого пути не хранится. № 36 закрыта в реально принятом пользователем объёме; точный критический путь не оставлять как автоматически разрешённую следующую часть.

## Следующий предлагаемый шаг и остаток продукта

Пользователь продолжает линию редактора, но после № 164 дал только bfe. Следующая реализация требует новой команды. Предложенная область: материалы, рецепты и несколько входов сборки. Она достаточно большая для проверки по коду и предложения небольших частей до старта. Не обещать весь остаток № 38 одним маленьким изменением.

При возобновлении сначала сверить реальные ограничения compileEditableProcess, ProcessDraft, configFromDraft, портов поля, хранения и JSON. Сейчас рецептов столько же, сколько постов, у каждого один вход и отдельный выход; ProcessDraft содержит одну inputMaterialId/inputQuantity. Порты и helper предполагают один вход и выход. Произвольное создание материалов и рецептов и управление несколькими источниками отсутствуют. Нужно согласованно расширять формы и проверки, сохраняя общий EditorConfig и compileConfig, а не вводить вторую расчётную модель. Не сбрасывать молча неподдерживаемые настройки и не терять ID существующих объектов.

Критерии готовности выбранной следующей части: пользователь выполняет согласованную операцию через UI, неправильная правка объясняется, сохранение/копирование/JSON и повторный запуск сохраняют условия, прежняя цепочка и развилка не ломаются. Сборки нельзя объявлять готовыми без фактического сценария с несколькими входами. Формы и клавиатура остаются альтернативой мыши. Для продуктовых изменений нужен npm run ci и приёмка нового пользовательского пути; расширять приёмку только под новые изменения.

В общем продукте ещё остаются остальные настройки полного редактора № 38, A/B, URL, прогресс, остальные уроки, исполнение DBR и окончательная межбраузерная приёмка. Это цели, не разрешённая очередь. № 36 закрыта в принятом смысле через № 134–137, точный критический путь не является незавершённой второй частью. № 66/69 закрыты. Публикация в npm отклонена. Не возобновлять DBR, первые три урока или другую продуктовую область без команды.
