## Состояние продукта и UI

Есть событийный движок с точными количествами/стоимостью, FIFO, явными ацикличными маршрутами, приоритетами, несколькими материалами/производителями, сборкой/разделением, обработочными и транспортными партиями, циклическими планами/наладками, наследованием буферов, четырьмя распределениями времени, обслуживанием, обедом/ночью/подменой и скрытым браком/контролем.

Работают восемь технических примеров: balanced, queue, blocking, split, assembly, batches, plans, quality. Это ещё не десять законченных уроков. Исходный UI-горизонт одна смена 08:00–17:00 с обедом 12:00–13:00. Движок поддерживает несколько дней, UI пока не предлагает настройку многодневного горизонта.

Сценарий и управление визуально разделены. Seed/CV в строке заголовка параметров. Пояснение времени/обслуживания/качества слева, поля справа; на узком экране колонки складываются. Прогноз/эксперимент/наблюдение занимают три колонки, разбор две; основной текст сценария 18 px. Есть RU/EN, system/dark/light, шаг, остановка, новый прогон, скорость и пауза на схеме. В storage сохраняется только необязательная тема с schemaVersion 1.

Новый прогон сохраняет применённые настройки. Смена примера сбрасывает буферы, распределение queue, обслуживание, подмену и quality к исходным. Plan/batchProfiles остаются состоянием App; полного сброса всех параметров одной кнопкой нет. Draft применяется отдельной кнопкой; смена языка его не применяет. ## Ключевые предметные контракты

Буферы: глобальные BufferDefaults.input/output наследуются и переопределяются по постам; есть quantity/infinite/materials, у входа также shift с десятичной долей. При отсутствии глобального входа inherit использует 0.5 смены, выхода 0. Норматив h×S×A[m]/C исключает общий обед даже при подмене; C включает среднюю обработку и циклические наладки, включая последний→первый рецепт, но не обслуживание/брак. Для bounded C считается точно в bigint-шестых долях ms (cycleWorkMs может быть numerator/6). Расчётный вход поднимается до полного комплекта, явно слишком маленький отклоняется. Сырьё округляется до микроединицы, выход поста до целой штуки. Читать inputCapacity/outputCapacity. Подробности [BUFFERS.md](BUFFERS.md).

Партии/планы: batches строки и repetitions обработочной партии различаются. Sequential резервирует весь комплект, завершает повторения по одному; simultaneous завершает k одним циклом. Вход/резерв/held/output непересекающиеся. Достигший порога held можно передавать; последний остаток партии передаётся ниже порога. Частичная выгрузка и held блокируют новый запуск. План циклический, недоступная строка не пропускается. Setup ждёт комплект, но резервирует только после наладки; тот же recipeId не требует её, initialRecipeId может назначить первую. Наладка не расходует RNG ordinal обработки. См. [SETUPS.md](SETUPS.md).

Распределения: processing задаёт timeMs/cv либо distribution, формы не смешиваются. Constant, lognormal(mean, CV 0–2), uniform(min/max), triangular(min/peak/max), положительные безопасные ms. В resolved среднее/CV, bounded могут иметь дробное среднее. Вырождение нормализуется. RNG ключ: seed, stationId, recipeId, operationOrdinal, purpose, sampleIndex. Выборка один раз на начале, purpose=processing отдельно от defect, округление минимум 1 ms. Queue DurationPanel меняет только work, соседи по 3 минуты. Quality использует постоянное время, общего CV в его UI нет. См. [VARIABILITY.md](VARIABILITY.md).

Календарь: модельные целые ms от начала первой смены, без Date/часового пояса. Дни без выходных; durationMs до конца целого числа смен. Обед/ночь сохраняют остатки операций. Завершения на границе учтены до календаря; новые операции на горизонте не начинаются. Источники всегда используют общий календарь, попытки индексируются накопленным рабочим временем, а не сбрасываются каждый день.

Обслуживание: enabled:false либо durationMs и хотя бы один положительный порог активной обработки/завершённых повторений. Ноль/пропуск отключает порог. В simultaneous считается k повторений, не число выходных штук. Требование внутри операции имеет operationVersion; полная партия и held освобождаются до обслуживания, выгрузка в свой output освобождает пост. Следующий вход для обслуживания не нужен. Отсрочки batch/output/calendar отмечаются при положительно прошедшем времени. После обслуживания оба счётчика сброшены, план/ordinal сохранены. lastMaintenance одна запись; обслуживание не добавляет processingMs происхождения. MaintenancePanel только prep в batches. См. [MAINTENANCE.md](MAINTENANCE.md).

Подмена: lunchReplacement позволяет выбранному посту начинать/продолжать обработку, наладку и обслуживание в общем обеде; ночью все останавливаются. Пост без подмены может принять материал в обед, но не работать. Источники сырьё в обед не выпускают. lunchBusyMs считает только фактическую занятость, без голодания/блокировки. lunchCost = ставка × накопленные ms / 3600000, ближайшая микроединица, половина вверх; расчёт от накопленного времени независим от шага. Доплата не капитализируется в материал. См. [LUNCH_WORK.md](LUNCH_WORK.md).

Качество: необязательная defectProbability 0–1 относится к каждой выходной штуке; отсутствие и 0 эквивалентны. У сырья собственного дефекта нет. При p=0/1 uniform не вызывается. FIFO-комплекты повторений сохраняют свои признаки; плохой комплект не заражает соседние. Время/стоимость распределены с остатком, в simultaneous sampleIndex различает штуки/повторения. Доли сохраняют признаки, большого детерминированного выхода не разворачивать в объект на штуку.

Контроль: inspection строго 1 A → 1 A, собственный p=0; фильтрует доли, не создаёт материал/дефект и не увеличивает produced/consumed. 0.6 годного + 0.4 плохого даёт 0.6 прохода и 0.4 списания. Возраст/стоимость/processingMs сохраняются, время контроля делится на все доли. Активное время/номинальные повторения включают плохие проверки для обслуживания. Финальная бесплатная проверка market удаляет брак без продажи. DAG по постам, маршруты явные; одинаковый материал не разрешает цикл/обход.

Агрегаты line.inspections по station/material содержат checked/passed/scrapped и completedRepetitions/processingMs, checked=passed+scrapped. Line.scraps по detectedAtId/material/точному набору defectSourceIds содержат количество, стоимость и вектор processingMs. Время/стоимость сериализованы строками. Несколько источников не задваивают списание. ID constructor/__proto__/toString являются данными: Map/Object.hasOwn при чтении словарей. Scrap контроля fromId=toId, fromLocation=reserved; UI удаляет с поста, не передаёт в output. См. [QUALITY.md](QUALITY.md).

Quality: времена prep/work/finish 3/8/3, qc 1 минута, входы 8, исходно p=25%, prep, ранний qc, seed 42. Ранний/поздний переносит тот же qc, сохраняя seed/профиль/ёмкости/подмену; материал индивидуальной ёмкости qc следует позиции. При смене источника stationId/recipeId ключ RNG меняется, это иной эксперимент. QualitySummary читает только обнаруженные inspections/scraps, выбор поста для потерь является просмотром.
