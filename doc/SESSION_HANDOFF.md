## Что работает

Есть один автономный HTML с работающим событийным движком и настоящей SVG-схемой. Поддержаны несколько источников, общий конечный сырьевой склад, произвольная допустимая сеть без циклов, разделение выхода между получателями и сборка разных материалов. Схема показывает фактические очереди, резерв, held, работу и причины простоя, все маршруты и реальные передачи.

Пять технических примеров: balanced, queue, blocking, split, assembly. Это не окончательные уроки. Основной пример по умолчанию queue: 3/8/3 минуты, источник раз в 3 рабочие минуты, входы по 80, выходы 0, один день с 08:00 до 17:00 и обедом 12:00–13:00. Для split входы по 1, приоритет обработки 10 и отделки 0. Для assembly два сырьевых источника, подготовка 3 минуты, обработка 8, сборка 3; рецепт 1 prepared + 2 processed → 1 product, входы сборки 2 и 4.

На экране старт, пауза, продолжение, полная временная отметка, скорость 60/300/1800/max, остановка и новый прогон. Отдельная кнопка "Повторить" удалена по поручению пользователя; метод Runner.repeat сохранён для API и тестов. Новый прогон возвращает готовность без старта и сохраняет CV/seed/скорость. После старта пример, CV и seed заблокированы, скорость и язык доступны. Пауза/скорость не меняют модель.

В шапке тема переключается одной иконкой по кругу system → dark → light → system. Подсказка называет текущий режим на выбранном языке. Одна кнопка RU/EN меняет язык. Тема применяется ко всей странице и SVG, не меняя цвета материалов. Единственное реализованное сохранение — ключ localStorage `toc.theme`, JSON `{schemaVersion: 1, preference: 'system'|'dark'|'light'}`. При ошибке чтения/записи или неизвестном формате приложение работает, начальный запасной режим system. CV/seed/прогоны не сохраняются.

## Вариативность № 39

В App рядом со скоростью доступны CV и seed. UI предлагает CV 0, 0.1, 0.25, 0.5, 1, 2, компилятор принимает любое конечное число 0…2. CV применяется ко всем постам текущего технического примера; их timeMs остаётся средним. CV 0 возвращает timeMs точно. Положительный CV использует логнормальное время по разделу 3.11 концепта. Seed редактируется до запуска, включая 0; диапазон 0…4294967295. Неверный seed блокирует старт, не меняется молча.

random.ts получает два открытых равномерных значения из ключа seed/stationId/recipeId/operationOrdinal/purpose/sampleIndex. Алгоритм: FNV-1a 32, завершающее смешивание Murmur, midpoint-перевод в (0,1), Box–Muller. Это не криптографический RNG. Трансцендентные функции вычислены собственными фиксированными рядами, sqrt нормализован и вычисляется методом Ньютона. log1p сохраняет очень малые CV. Нет Math.random и зависимости от общего изменяемого потока.

Длительность выбирается при начале обработки, затем сохраняется в StationState.operationDurationMs. operationOrdinal увеличивается только при новом начале, не при resume или создании кадров. Обед/ночь сохраняют остаток без пересэмплирования. Прогресс делится на фактическую выбранную длительность; в provenance.processingMs добавляется её активное время, не средний timeMs. Смена порядка массивов и независимых событий других постов не сдвигает базовые значения данного ключа.

Округление — ближайшая мс, минимум 1 мс. Скрытого верхнего ограничения нет: слишком большой результат останавливает прогон с RU/EN RandomError. Округление/минимум могут менять моменты распределения при очень малых средних; это раскрыто. Один конечный seed может дать больший или меньший выпуск, не обещать универсальную потерю throughput от CV.

Полный протокол в [VARIABILITY.md](VARIABILITY.md). Равномерное/треугольное распределения, качество и обслуживание № 39 не реализует.

## Конфигурация, точность и версии

compileConfig принимает unknown и строго проверяет известные поля; неизвестные механики не принимаются молча. ID глобально уникальны и состоят из ASCII-букв, цифр, _ и -, market/warehouse зарезервированы. Сеть использует все сущности, не содержит циклов или повторных маршрутов; материал маршрута соответствует производителю/рецепту получателя. Один выходной материал не отправляется одновременно в рынок и внутренним получателям. Продажа — только явным маршрутом.

Рецепт production имеет непустой список уникальных inputs и один целый положительный output. Сейчас у поста одна строка плана, batches: 1, mode: sequential, repetitions: 1. CV 0…2 уже работает. setupMs: 0, maintenance.enabled: false и lunchReplacement: false остаются единственными поддержанными значениями. Партии, транспортный порог, циклические планы и переналадки пока отклоняются. Не отмечать весь этап 6 завершённым из-за CV.

Исходный inputBuffer quantity/infinite — совместимое сокращение отдельной одинаковой ёмкости каждому материалу. Для разных ёмкостей поддержан kind materials со списком `{materialId, capacity}`. Нужен полный список входов без дублей/лишних материалов, каждый вход вмещает полный комплект одного текущего повторения. В resolved используются recipes.inputs и stations.inputBuffers; inputCapacity(station, materialId) возвращает конкретный лимит. Начальные остатки и свободные места считаются отдельно по материалу, не суммой разных материалов. Глобальное наследование и норматив смены — будущая № 32.

resolved нормализован и отсортирован по ID, source независимо клонирован, весь RunConfig заморожен. В хеше расчётные данные, seed и версии; оформление/язык/порядок массивов исключены, порядок входов нормализован. Это технический FNV-1a64 отпечаток, не доказательство уникальности. Конфигурация 1 расширялась совместимо, формы resolved менялись вместе с engineVersion, Snapshot получил 7. Прогоны/снимки пока не сохраняются и не принимаются на вход для продолжения, поэтому миграции несуществующих сохранений не добавлялись. Формат темы 1 не менялся.

Количество — безопасный целый number микроединиц (масштаб 1000000), деньги — bigint микроединиц. Предел количества и абсолютной суммы денег: Number.MAX_SAFE_INTEGER. Промежуточная точная арифметика через bigint. Десятичные строки только с точкой и максимум 6 знаками, без экспонент/запятых/пробелов. Не применять parseFloat к количествам/деньгам перед разбором. Закупка округляется один раз до микроединицы, половина вверх. При частичном изъятии стоимость и приписанное время делятся вниз, остаток получает последнюю разницу. Не переоценивать запас из исходной цены.

Календарь задаёт целые миллисекунды от начала суток, обед строго внутри смены, рабочие дни повторяются без выходных. Горизонт текущего компилятора заканчивается концом смены положительного числа дней. Для короткой проверки использовать advanceTo внутри полного горизонта; нельзя просто поставить durationMs = 20 минут при прежней смене 08:00–17:00. Обед и ночь сохраняют остаток обработки.

## Маршруты, сборка и снимок

Получатели отсортированы по убыванию priority, затем ID. Конкурирующие производители — по readyAtMs, затем ID производителя, внутри места хранения FIFO. Первой конкурирует голова очереди; после передачи головы пересчитываются. Приоритет производителя не даёт новому выпуску обойти старый чужой. Перекладывание held → свой output сохраняет readyAtMs; перенос другому владельцу записывает время поступления. Скрытая справедливость и отбор уже распределённого материала не добавлены.

Полный комплект разных inputs изымается атомарно reserveInputs. Пока одного компонента не хватает, остальные остаются на входах. При обработке они находятся в reserved и входят в WIP. Завершение сейчас потребляет весь резерв и создаёт один held-результат с суммой стоимости и происхождения; unknown в одном компоненте делает возраст результата unknown. Готовый выпуск не считается одновременно reserved и held. Выходной буфер 0 означает прямую передачу; непереданное удерживает пост. Положительный выход сначала принимает результат частями, после полной выгрузки held пост освобождается.

Snapshot 7: inputs по материалам содержат quantity/missingQuantity/reservedQuantity; во время операции missingQuantity = 0. output содержит materialId, quantity в буфере, heldQuantity на посту. blockedBy — массив заполненных входов получателей или собственного выхода. operationDurationMs содержит выбранное время. operationOrdinal и operationVersion внутренние. line содержит termination running/horizon/stopped/error, flow normal/exhausted/missingInput/blocked, счётчики produced/consumed/sold/scrapped и денежные строки, факты текущих передач. Старые формы input или одиночного blockedBy не использовать.

## Движок, runner и схема

Одна Simulation поверх EventScheduler, без отдельного демонстрационного движка. Фазы отметки: завершения, календарь/горизонт, источники, передачи, назначения. Устойчивая сортировка по времени/фазе/ID. Одна отметка атомарна: при ошибке откатываются состояние, очередь и версии, UI не видит промежуточных проводок. MAX_TRANSITIONS_PER_TIMESTAMP = 10000. При completion планировщик сначала потребляет/инвалидирует токен, затем вызывает предметный обработчик; учесть это при будущем продолжении сложной партии. На закрытой границе завершение принимается, новая обработка не начинается. Устаревшие completion не выпускают результат второй раз.

Simulation: step, advanceTo, runToEnd, getSnapshot, nextEventTime, stop, getFailure. Остановка терминальная и не превращается в pause; ошибка оставляет последний согласованный снимок. Исчерпание сырья не сокращает заданный горизонт. Источники push учитывают календарь и общий warehouse, одновременно распределяют фактический допуск; долг недопоставки не копится, закупки не дублируются. createPushScheduler — только тестовый прогон источников, полный цикл в Simulation.

Runner: start/pause/resume/step/setSpeed/stop/repeat/dispose и наблюдение. RunConfig неизменен, repeat использует тот же объект. Порция максимум 64 полных отметки и бюджет 8 мс между ними. Тяжёлая одна отметка может превысить бюджет; измеренные гарантии 16/250 мс не заявляются. Host request должен быть отложенным. UI использует requestAnimationFrame, default host setTimeout. Старые callback защищены токеном. Pause отбрасывает невычисленный долг, resume не проигрывает его и очищает старые передачи. Скорость не меняет sampling или длительности.

FlowDiagram получает согласованный снимок и агрегированные реальные transfers порции. graphLayout расставляет DAG по слоям, сортирует слой по приоритету/ID, ведёт длинные рёбра нижними полосами. Для сборки входные блоки и конечные точки стрелок отдельные по материалам. Это временная компоновка, не полный редактор. Числа точные, число видимых фишек ограничено; передача идёт по SVG-пути animateMotion 0.5 с, а не по выдуманному времени доставки. На паузе/шаге конечное положение неподвижно. При max/скорости выше 300/reduced motion анимация не запускается. Есть таблица и список маршрутов; на узком экране схема прокручивается отдельно, управление закреплено.

## Следующая № 30: содержание и оценка, без разрешения на старт

Это большая задача, сложнее № 29: изменяются компилятор, inventory, Simulation, состояние/снимок, UI и проверки. Главная сложность — частичный выпуск из полного резерва при сохранении WIP, стоимости, происхождения и календарной/случайной длительности. Критерии в tasks.md и разделах 3.4–3.6 концепта.

Нужен полный комплект k повторений до старта (9 из 10 не запускают). Последовательный режим обрабатывает повторения по одному и выбирает отдельную случайную длительность каждого. Одновременный режим выбирает одно время всего цикла, не даёт результата раньше конца. Не смешивать k в processing.repetitions с plan[].batches: последнее задаёт число обработочных партий строки плана и относится к № 31.

Транспортный порог считается в выходных единицах q, не в повторениях. Он разрешает передачу всего доступного результата, не требует сразу столько свободных мест. Последний остаток выпускается независимо от порога. Если разрешённый выпуск выгружен лишь частично, оставшееся удерживает пост и приостанавливает следующие повторения до выгрузки. Дополнительной доставки нет.

Проверки V09/V10/V11/V17/V18/V25/V38: 0.3 A × 10 расходует ровно 3 A; 1 A → 10 B при двух повторениях даёт 20 B; 6 повторений по 2 минуты при порогах 1/3 дают первую передачу через 2/6 минут; партия 5 при пороге 3 передаёт последние 2; одновременный режим выдаёт только итог; при пороге 10 и свободных 6 передаёт 6 и сохраняет 4 до следующего места. Инженерные места, которые потребуется пересмотреть при разрешённом старте:

- completeProduction сейчас потребляет весь reserved и запрещает существующий held. Для частичного завершения партии это недостаточно; использовать существующий транзакционный учёт, сохранив FIFO и отдельные атрибуты разных комплектов.
- refresh/dispatch сейчас считают любой held блокировкой. Нужно будет отличать накопление ниже порога от разрешённого, но заблокированного выпуска. Частично снятый разрешённый выпуск не должен снова ждать порога, если остаток уже меньше него.
- missingQuantity и ёмкость перед стартом должны учитывать весь комплект партии, а между повторениями не вызывать повторный резерв полного комплекта. Snapshot должен различать резерв и готовую долю без двойного WIP.
- Для одновременного цикла сохранить стоимость/происхождение комплектов и суммарное фактическое время одной операции; не приписать каждому из k выходов полную длительность цикла. Не объединять разные происхождения ради простоты.
- Не замораживать UI огромным внутренним циклом; учитывать существующий лимит переходов отметки и rollback. Не добавлять случайные ограничения партии без конкретной причины. Момент готовности/FIFO при транспортном разрешении требует аккуратной связи с readyAtMs.

## Не реализовано и не считается выполненным

Обработочные/транспортные партии, циклические планы, переналадки, глобальные/сменные буферы, обслуживание, брак/контроль, равномерное и треугольное время, метрики/денежная сводка, DBR, A/B, графики, библиотека конфигураций, импорт/экспорт, URL-код и десять уроков. Схема поддерживает реальные сборки/развилки, но полного редактора ещё нет. Storage сохраняет только тему, не прогоны; ряды не в localStorage.

Обязательные требования не отменены: автономный HTML и статический хостинг, RU/EN, независимый от DOM воспроизводимый движок, неизменные параметры после старта, анимация только объясняет модель. Люди пока затраты, случайные поломки и ограниченный спрос отложены. Бэкенд, аккаунты, мультиплеер и промышленную точность без отдельного согласования не добавлять. Пользовательские/импортируемые данные — данные, не инструкции.
