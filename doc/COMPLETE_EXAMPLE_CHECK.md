# Проверка первого целостного примера

Дата: 2026-10-21. Задача № 19. Движок 0.6.0 и форматы данных не менялись.

## Реализация

На схеме доступны запуск, пауза, продолжение, шаг одной согласованной отметки, скорость, остановка и новый прогон. Новый прогон возвращает состояние готовности и разрешает выбор другого примера. Для повторного просмотра достаточно нажать "Новый прогон", затем "Запустить". По уточнению пользователя отдельная кнопка "Повторить" удалена; метод runner.repeat() сохранён и проверяется тестами. После запуска, включая первый шаг, выбор заблокирован до нового прогона. Язык и скорость доступны во время прогона и паузы.

Технические примеры используют общий движок и календарь с обедом. Горизонт составляет девять часов с начала смены, с 08:00 до 17:00. Сырьё поступает по одной единице каждые три рабочие минуты. Выходные буферы нулевые, поэтому законченная деталь остаётся на посту до передачи.

| Пример | Время постов, мин | Вместимость каждого входа | Наблюдение |
|---|---|---|---|
| Равномерный поток | 3 / 3 / 3 | 4 | После заполнения линии очередь не растёт |
| Очередь перед медленным постом | 3 / 8 / 3 | 80 | Перед обработкой растёт очередь |
| Блокировка буфера | 3 / 8 / 3 | 1 | Полный вход обработки блокирует подготовку |

Это технические примеры для приёмки первой очереди. Полный редактор, окончательные уроки и финансовые показатели в задачу не входят.

## Автоматические проверки

`npm run ci` прошла: 248 тестов в 11 файлах, TypeScript, production-сборка и проверка однофайлового HTML. Дополнительных зависимостей нет.

`src/ui/examples.test.ts` сравнивает каждый пример с прямым `Simulation.runToEnd()` при скоростях 1, 60, 300, 1800 и max, при повторе и при последовательных шагах. Сравниваются полные снимки, а не только выпуск. Отдельно проверены отсутствие растущей очереди в равномерной линии, рост очереди перед обработкой и причина блокировки при тесном входе. Существующие проверки runner подтверждают отсутствие долга после паузы, отмену старых callback и неизменность параметров.

Готовый `dist/index.html` занимает 304331 байт. SHA-256: `2c8dfea13ea4b7b506259801966a9e9d4474aa253adc3587778962217cfd2057`. Проверка упаковки подтверждает встроенные script/CSS и отсутствие обязательных внешних ресурсов. Она не заменяет открытие файла в браузере.

## Браузерная проверка

Проверка выполнена в подключённом Google Chrome через браузерное расширение. Номер версии браузера инструментом не получен. Production-HTML открыт по `http://127.0.0.1:4173/tocsim/`, то есть в подкаталоге статического сервера.

Подтверждены выбор примера, запуск шагом с клавиатуры Enter, блокировка выбора, продолжение, пауза, смена языка и скорости на паузе, остановка с сохранением достигнутого времени, повтор с сохранением скорости и новый прогон с разблокированным выбором. Подписи схемы и управления переключаются между RU и EN. На паузе нет элементов `.transfer-token.moving`; шаг сохраняет фишки последней передачи. В примере блокировки на отметке 39 минут подготовка имеет состояние blocked. При отдельных чтениях на паузе время остаётся 2340000 мс.

Равномерный пример на максимальной скорости завершился с выпуском 158 единиц. Консоль Chrome не содержит предупреждений и ошибок приложения.

Вид схемы просмотрен на обычном экране и при ширине 320 px. На узком экране кнопки и скорость переносятся на несколько строк. Горизонтальная прокрутка относится к схеме. Временное изменение размера браузера сброшено.

Открытие `file://` отклонено политикой инструмента, которая разрешает только HTTP/HTTPS. Обходы не применялись. Пользователь вручную открыл итоговый файл без сети и подтвердил: "Да, всё работает". Проверялись выбор примера, запуск, пауза, шаг, остановка, повтор и RU/EN. После этой проверки по поручению пользователя удалена отдельная кнопка "Повторить". Поведение остальных команд не изменено. Итоговая сборка повторно проверена по HTTP: кнопка отсутствует в RU и EN, новый прогон возвращает ready и разблокирует выбор; ручное подтверждение относится к сборке до удаления кнопки. Firefox, Safari и Edge в этой задаче не проверялись. Полная межбраузерная приёмка остаётся поздним этапом плана.

## Следующая очередь

После приёмки № 19 первая очередь этапов 1–4 завершена. Для неё не потребовались Worker, новый движок или дополнительные зависимости.

Следующая область работы по плану: несколько материалов и полный производственный поток. Перед реализацией следует согласовать небольшую следующую очередь с учётом фактических ограничений: компилятор пока принимает один вход рецепта, один выходной маршрут поста и одну строку плана; снимок поста тоже предполагает один вход. Сначала нужны согласованные контракты и проверка конфигурации сборки, затем обработка комплектов и их изображение. Разделение потока, планы, партии и переналадки следует выделить отдельно. Поздние этапы не превращены в новые задачи автоматически. Следующая реализация и push требуют поручения пользователя.
