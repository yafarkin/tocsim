На главном экране рядом со скоростью находятся CV и редактируемый seed. UI предлагает CV 0, 0.1, 0.25, 0.5, 1 и 2; компилятор принимает любое конечное CV от 0 до 2. Значение применяется к обработке всех постов выбранного технического примера. Средние времена и настройки источников остаются прежними. CV и seed фиксируются после запуска, включая первый шаг; скорость доступна во время просмотра. Новый прогон сохраняет выбор CV/seed и скорость. Seed допускает целые 0…4294967295; неверное значение объясняется и блокирует старт. Параметры не сохраняются в storage.

CV 0 оставляет время точно равным timeMs. При положительном CV используется согласованное логнормальное распределение: sigma² = ln(1 + CV²), длительность = mean × exp(sigma × Z − sigma²/2). Z получается преобразованием Box–Muller. Значение округляется до целых миллисекунд с минимумом 1 мс. Скрытого усечения сверху нет; превышение безопасного числового диапазона останавливает прогон с диагностикой. На очень малых средних округление и минимум могут изменить фактические моменты распределения, что следует из явного правила 1 мс.

Генератор не использует Math.random или глобальное изменяемое состояние. Ключ содержит seed, stationId, recipeId, operationOrdinal, purpose и sampleIndex. Два открытых равномерных значения получаются FNV-1a 32 с завершающим смешиванием Murmur; это генератор для учебной симуляции, не криптографический алгоритм. Счётчик операции увеличивается только при начале обработки. Перестановка массивов, обновление UI, скорость и пауза не сдвигают поток. Обед и конец смены сохраняют уже выбранную длительность.

Встроенные трансцендентные функции JS-движка не используются. log1p сохраняет малые CV без потери variance при сложении с 1; sqrt нормализует очень малые числа перед итерациями. Численные операции и число итераций входят в версию RNG. Эталонные округлённые длительности также независимо сверены с Python math. ## Расширенные распределения, № 64

Профиль строки плана принимает прежние timeMs/cv либо поле distribution. Вместе задавать обе формы нельзя. Новая форма поддерживает:

| kind | Параметры в миллисекундах | Среднее |
|---|---|---|
| constant | timeMs | timeMs |
| lognormal | meanMs, cv | meanMs |
| uniform | minMs, maxMs | (minMs + maxMs) / 2 |
| triangular | minMs, peakMs, maxMs | (minMs + peakMs + maxMs) / 3 |

Границы и исходные длительности являются безопасными положительными целыми миллисекундами. Нужны min ≤ peak ≤ max и min ≤ max. CV логнормального профиля конечен и находится от 0 до 2. Лишние поля, неверные границы и переполнение отклоняются до создания состояния с ConfigError RU/EN и исходным путём строки плана. Среднее и CV равномерного/треугольного профиля вычисляются, отдельно вводить их нельзя.

source сохраняет исходную форму и параметры. resolved.plan содержит timeMs как среднее и cv как рассчитанный коэффициент. Для невырожденных bounded-профилей рядом сохранён distribution с границами. Legacy и явная форма логнормального/постоянного профиля нормализуются одинаково. При min=max и min=peak=max диапазон нормализуется в константу. Равные resolved дают одинаковый calculationHash в одной версии движка. Объекты глубоко заморожены и не разделяют изменяемые ссылки с входом.

Равномерная выборка использует min + (max−min)×u. Треугольная использует обратную функцию распределения с ветвлением по (peak−min)/(max−min). Квадратный корень вычисляется существующим фиксированным методом Ньютона. Ключ и исходный uniform прежние, purpose='processing', sampleIndex=0. Константа не требует случайного значения, но счётчик операции по-прежнему увеличивается при начале обработки. Длительность выбирается один раз и округляется до целых миллисекунд. Календарные паузы не выбирают её заново. Для логнормального распределения сохранены прежние операции, sampleIndex=0/1 и эталоны; скрытого усечения нет.

CV равномерного профиля равен (max−min)/(sqrt(12)×mean). Для треугольного стандартное отклонение равно sqrt(((peak−min)²+(max−min)²+(max−peak)²)/36). При вырожденных границах CV=0. Речь идёт о теоретических моментах до округления выборки. Для очень коротких длительностей округление до миллисекунд может изменить наблюдаемые моменты.

Норматив буфера использует точное среднее до округления. meanDurationSixths хранит шестые доли миллисекунды в bigint. Этого достаточно для целых, полуцелых и третей миллисекунды. Суммы обработки, числа партий и циклических переналадок рассчитываются в этой шкале. Округление ёмкости выполняется в конце по материалу. bufferCalculations.cycleWorkMs сохраняет целую десятичную строку для целого цикла, а для дробного строку numerator/6. Например, 8/6 означает 4/3 миллисекунды. Расчёт с min=1, peak=1, max=2 и h=.000001 даёт 21.6 детали до округления и 22 после. Равномерное 1/2 мс даёт среднее 1.5 мс и ёмкость 20 при том же h.

## Панель № 64

В примере очереди панель «Время обработки» относится только к рецепту поста «Обработка». Подготовка и отделка занимают по 3 минуты без разброса. Список выбирает постоянное, логнормальное, равномерное или треугольное время. Поля показаны только для выбранного способа. При диапазонах среднее/CV вычисляются и показаны текстом. Отдельная кнопка применяет черновик. Рядом подписаны текущие применённые среднее/CV. При наследуемом входе предварительно показано его расчётное количество. Невалидный черновик блокирует применение и не меняет текущий RunConfig.

В этом примере общий переключатель CV скрыт, seed остаётся рядом со скоростью. В остальных примерах общий CV работает как прежде. После старта и первого шага параметры заблокированы. Новый прогон сохраняет применённое распределение, seed и скорость, смена примера возвращает исходную настройку времени очереди. Панель принимает минуты с точкой или запятой, до шести десятичных знаков; значение должно выражать целые миллисекунды. На схеме среднее и CV ограничены по числу показываемых знаков. Расчёт использует полную точность.

Пример 2/3/8 минут имеет среднее 13/3 минуты. При входе на 0.5 смены посту рассчитывается ceil(240/(13/3))=56 деталей. Изменение распределения пересчитывает этот норматив только до старта.
