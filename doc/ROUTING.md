# Разделение потока и конкуренция производителей

Дата: 2026-10-21. Задача № 28. Движок 0.7.0, конфигурация 1, снимок 5, RNG none-1.

## Поддерживаемая сеть

Пост может иметь несколько явных выходных маршрутов и получать один входной материал от нескольких производителей. Сеть не содержит циклов, повторных маршрутов и неиспользуемых сущностей. Ссылки и соответствие материала рецептам проверяются компилятором. Для одного выпуска нельзя одновременно задать рынок и внутреннего потребителя. Продажа остаётся возможной только по явному маршруту. Несколько входных материалов рецепта остаются задачей № 29.

Получатели сортируются по убыванию приоритета, затем по стабильному ID. Каждый получает не больше свободной ёмкости. Уже переданный материал не перераспределяется обратно. Приоритет может лишить другую ветвь материала; выравнивание или скрытая справедливость не добавлены.

Конкурирующие производители распределяют готовые запасы по времени готовности, затем по ID производителя. Приоритет производителя не даёт его новому выпуску обойти старый выпуск другого поста. Внутри каждого места хранения действует существующая FIFO. После передачи проверяется следующая голова очереди, поэтому один пост с несколькими старыми записями сохраняет очередь перед более новым выпуском другого.

Для этого StockState и снимок запаса содержат readyAtMs. Начальные записи имеют 0, новый выпуск получает модельное время завершения. Перенос удерживаемого результата в собственный выходной буфер сохраняет это время. При передаче другому владельцу записывается время поступления. Время начала происхождения в provenance остаётся отдельным признаком и не подменяет порядок распределения.

Сначала распределяется доступный выходной запас, затем удерживаемый результат выгружается в освободившуюся выходную ёмкость и снова ставится передача той же отметки. При нулевом выходе удерживаемый результат сразу конкурирует за входы получателей. Частичная передача не теряет стоимость и не освобождает пост до полного снятия удерживаемого результата.

## Снимок и схема

StationSnapshot.blockedBy теперь является массивом. При прямой передаче он перечисляет заполненные входы всех получателей в порядке приоритета; при полном собственном выходном буфере указывает его. При отсутствии удерживаемого результата массив пуст. Схема перечисляет все причины, а не выбирает первого соседа.

graphLayout размещает источники и посты по слоям допустимой сети. В одном слое сначала показан пост с большим приоритетом, затем используется ID. Это порядок отображения, а не новый порядок событий. Длинные маршруты обходят посты по нижним полосам. Поддерживаются несколько источников и сходящиеся маршруты одного материала. Полная компоновка конструктора и сборки пока не заявляется.

Стрелки, подписи маршрутов и текстовая таблица показывают все явные связи. Под названием поста виден приоритет. Фишки следуют фактическому SVG-пути передачи через animateMotion, а не перемещаются только по горизонтали. На паузе и после шага они стоят в конечном положении. На высокой скорости или при уменьшенном движении анимация не запускается. Управление остаётся закреплённым при прокрутке высокой схемы.

Технический пример "Разделение потока" использует подготовку 3 минуты и два альтернативных поста по 8 минут. Оба получают одну и ту же деталь и выпускают один и тот же конечный материал. Приоритет обработки 10, отделки 0, входы по одной детали. Сборки между ними нет.

## Проверки

`npm run ci` прошла: 270 тестов в 13 файлах, TypeScript, production-сборка и проверка автономного HTML. Новые проверки охватывают V13, одинаковые приоритеты, недопустимые маршруты, несколько производителей, нулевые и положительные выходные буферы, частичную передачу и полный список блокирующих получателей.

Конкурирующие производители проверены с разным временем готовности и с одинаковым временем при противоположных приоритетах. Стоимость отдельных запасов позволяет проверить, какой выпуск фактически попал к получателю. Подтверждено сохранение readyAtMs при переносе в выходной буфер и прохождение старого начального запаса перед новым выпуском.

На каждой отметке проверены стоимость, остатки, проводки по каждому материалу и вместимость буферов. Полный прогон, шаги и нерегулярные продвижения совпадают; перестановка массивов не меняет хеш или снимок. Для всех четырёх UI-примеров runner на скоростях 1, 60, 300, 1800, max, по шагам и при повторе совпадает с прямым движком. Регрессия линейной модели проходит.

Проверка схемы отдельно покрывает несколько источников, пропуск слоя длинным маршрутом, устойчивую компоновку при перестановке массивов и обе причины блокировки на RU/EN.

## Браузерная приёмка

Production-HTML открыт в подключённом Google Chrome по HTTP в подкаталоге `/tocsim/`. Новая автоматическая навигация на file:// не выполнялась из-за ранее установленного запрета инструмента. Отсутствие обязательных внешних ресурсов проверено упаковкой; новая ручная проверка offline и межбраузерная приёмка не заявляются.

Просмотрены обе ветви, приоритеты, очередь и фишки в тёмной и светлой темах. На отметке 1440000 мс подготовка заблокирована, на схеме видны "Заполнен вход: Обработка; Заполнен вход: Отделка" и соответствующие английские подписи. Пауза даёт 0 animateMotion, при обычном просмотре такой элемент присутствует. При ширине 320 px управление переносится по строкам, а схема прокручивается отдельно. После вертикальной прокрутки кнопки остаются сверху. Временный размер браузера сброшен.

На максимальной скорости пример завершился на 32400000 мс с выпуском 117 изделий. Консоль Chrome не содержит ошибок и предупреждений приложения.

## Совместимость и продолжение

Конфигурация схемы 1 расширена без изменения её структуры; прежние конфигурации принимаются. Версия движка повышена, поскольку изменился порядок конкурирующих передач. Снимок схемы 5 несовместим с формой blockedBy из схемы 4. Снимки не сохраняются и не принимаются на вход для восстановления; миграция несуществующих сохранений не добавлялась. Существующая сохраняемая настройка темы остаётся схемы 1 без изменения формата.

Следующая реализация № 29 требует ответа пользователя после проверки и коммита № 28. Она добавит несколько материалов в комплект. Подсветка критического пути и узла записана отдельно в № 36 на будущее; она требует определения критериев и готовых метрик, и в № 28 не реализована.
